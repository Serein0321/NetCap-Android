# NetCap

**Android Root 悬浮抓包与通信观察工具**

NetCap 面向 Android 应用与游戏的通信调试，将流量采集、原始记录保存、手机内查看和文件导出整合到一个 APK 中。启动后通过悬浮球展开半透明工作台，在当前应用上方完成进程选择、开始/停止抓包、查看记录与导出，无需来回切换普通应用页面。

采集与手机内分析在本机完成，不依赖 AI 服务。你可以观察包的方向、大小、时间、通信端点和载荷，也可以导出 PCAP，在电脑上的网络分析工具中继续研究。首页 MCP 为可选服务，开启后持有令牌的客户端可以读取会话与数据包。

> **项目状态：开发测试版。** 当前版本为 `0.5.0-mcp-test`，新增首页 MCP 连接中心、独立后台服务和六项只读分析工具，保留文件工作区、TLS观察、12主题与采集胶囊。接入方式及本轮验证见 [MCP 说明](MCP.md)。真实 Root 抓包、物理局域网覆盖及长时间后台稳定性仍需设备验证。既有功能验证见 [验证记录](VERIFICATION.md)。

## 环境要求

- **Android 13 或更高版本**，目标 API 为 36。
- 主要手机架构为 **arm64-v8a**；构建也提供 x86_64 核心用于开发验证，未提供 32 位核心。
- 实际采集和读取完整进程信息需要 **Root**，并需要可用的 `su` 命令。
- Root 环境必须允许执行 APK 内置核心及创建抓包 socket；实际能力受系统、内核、Root 管理器和 SELinux 策略影响。
- 无 Root 时仍可使用已有会话查看、PCAP 导入和文件导出。

## 安装与快速开始

### 1. 安装并启动工作台

从仓库的 **Releases** 下载测试 APK，安装后打开 NetCap 的启动页并点击“启动”。按系统提示允许显示在其他应用上层，回到桌面或目标应用后点击悬浮球。

当前安装文件为 `NetCap-0.5.0-mcp-test.apk`。MCP 可在首页独立开启，无需先启动悬浮工具；详见 [接入说明](MCP.md)。

“启动”只启动工具服务，**不会自动开始抓包**。

### 2. 检查 Root

在悬浮工作台中进入“设置 → 诊断与维护 → 检查 Root 核心”，完成 Root 管理器授权。检查会尝试创建抓包 socket，而不只是判断设备上是否存在 `su`。

首次需要 Root 授权时，工作台会临时隐藏，为系统授权页面让出操作空间；完成后恢复。已有授权查询通道时，检查直接复用通道，在原检查弹窗中更新结果，避免重复隐藏整个工作台。若失败，保留完整错误输出用于排查。

### 3. 选择目标并抓包

1. 点击左上角应用图标，打开进程列表。
2. 选择目标应用，顶部会显示其身份及最近读取的内存快照。
3. 在“抓包”页点击“开始抓包”。
4. 收起工作台，在目标应用中执行要观察的操作。
5. 再次展开工作台，点击“停止并保存”。

进程列表仅保留标题与应用列表；按返回或点击弹窗外部可关闭。内存低于 900 MB 时显示 MB，从 900 MB 起显示 GB。

首次尚未选择应用时，点击开始抓包可在范围确认中选择“使用整机模式”；也可在“设置 → 采集策略 → 抓取范围”切换。选择具体进程后，应用模式按 UID 与 socket 信息关联，**不等同于精确的逐包 PID 采集**。

### 4. 查看和导出

- **数据**：浏览当前或选中会话的包，打开详情，查看通信字段、可读内容与完整原始字节。
- **历史**：点击会话打开概览，从概览打开数据、报告或导出；长按进入批量管理，支持工作分组及删除本地会话文件。当前查看的会话高亮。
- **设置**：选择保存目录、文件名前缀、协议、接口、背景不透明度与熄屏抓包选项。

导入与导出使用工作台内的路径选择器。默认保存和导出目录位于应用自己的外部文件目录；访问共享存储中的其他位置时，需要额外文件访问权限。

导出会先写入 `.partial` 临时文件，完成同步后再命名为目标文件；遇到同名文件会拒绝覆盖。

## 悬浮操作

- **拖动球**只移动位置；**点击球**展开工作台。
- 右上角 **×** 收起为球，正在进行的抓包继续运行。
- 停止并保存后，悬浮球仍保留；“设置 → 结束工具”才退出服务。
- 弹窗按层级操作，返回优先收起键盘，再关闭顶层窗口。
- 工作台背景可透出原应用，空白处仍接收触摸；系统保留手势及状态/导航区域由 Android 管理。
- 默认允许截图和录屏显示工具。
- “熄屏保持抓包”可保持 CPU 唤醒，会增加耗电；后台长期稳定性仍需设备实测。

## 数据查看

### 原始字节

原始记录采用“**偏移 / 十六进制 / 字符**”三栏网格，每 4 字节分组，避免长行自动折行造成错位。

通常窄屏每行显示 8 字节，宽屏显示 16 字节；极窄宽度或大字体下可降为 4 字节。字符栏直接映射可打印 ASCII，其余字节以中点表示。该视图只读，不会修改抓到的包。

### 可读内容与比较

可读视图可展示有效 UTF-8 文本或格式化 JSON。点记录查看，点勾选框选择；恰好选择两条后，点击比较图标查看载荷变化位置。长按记录可以查看同一连接、收藏或复制地址；收藏可改名或移除。

连接概览按通信端点归类并汇总包数与字节数。这里的归类和字节展示用于帮助观察，**不代表已经理解未知游戏协议或解密其内容**。

数据区分为“全部”“已保存”“关联”，各视图不混入数据。上方工具栏提供筛选、搜索、保存、比较、分组、选择和更多操作；长按图标可查看名称。

筛选支持协议、发出/收到/未知方向、包长度、可读文本/非文本。搜索支持文本与地址，或十六进制载荷魔数（任意位置/开头）。可读只表示文本解码条件成立，不表示已理解业务协议。

滑动接近边缘时自动分页，向上可补回较新的页面；手动浏览或勾选时停止跟随，避免新包冲走位置。“更多 → 跟随最新记录”可恢复。收藏只写 `bookmarks.json`，不改 PCAP/索引，也不会删除原包。

### TLS 连接与外观

TCP记录详情中的“TLS 连接”页签按需分析；“组织数据 → TLS连接分析”可从TCP连接列表进入。TLS 1.3 中已加密的字段明确显示不可见，Hello可见时间间隔不代表完整握手成功或耗时。全局配色位于“设置 → 外观与交互”。TLS边界见[TLS说明](TLS_THEME.md)，新主题画廊与采集胶囊见[使用说明](GALLERY_BUBBLE.md)。

### 文件工作区

历史页浏览实际保存目录，单击进入目录/打开文件，长按弹操作菜单。复制/剪切 → 进入目标文件夹 → 粘贴；可新建子目录和实际改名，删除会同步移除手机文件。会话目录内部可浏览，修改操作以整个会话为单位；正在采集的会话及其父目录受保护。旧分组标签不会自动搬动真实文件。文件操作边界见[FILES_WORKSPACE.md](FILES_WORKSPACE.md)，最新单击/长按与ZIP浏览见[DIRECT_OPEN.md](DIRECT_OPEN.md)。

## 保存和导出格式

| 格式 | 内容 | 适用用途 |
| --- | --- | --- |
| **ZIP** | 全部 PCAP 分段、索引、会话状态、收藏、归属证据、网络日志和未知包子目录 | 完整保留会话与扩展信息 |
| **PCAP** | 合并后的标准原始 IP 包记录 | 在电脑上的网络分析工具中继续分析 |
| **JSONL** | 网络字段及载荷字节 | 脚本处理、统计和自定义分析 |
| **TXT** | 完整原始记录的十六进制文本 | 阅读、检索及与其他记录对照 |

采集数据每 **64 MiB** 自动分段。方向、接口等扩展信息并不全部包含在标准 PCAP 内，需要保留这些信息时应导出完整 ZIP。

当前支持导入 PCAP 的 raw-IP、Ethernet（含常见 VLAN）、Linux SLL、IPv4 和 IPv6 链路类型；非 IP 记录会跳过并计数。**尚不支持 PCAPNG 导入。**

## 记录与完整性

NetCap 将数据接收、磁盘写入和界面浏览分开处理：

- 接收与写盘通过 **16 MiB 有界队列**连接，界面刷新不决定原始记录是否保存。
- 原始 PCAP 字节刷新后才发布对应索引，减少实时查看读到尚未写入数据的情况。
- 正常停止时先排空队列，检查写入、刷新及关闭错误。
- 保存目录和采集配置在会话开始时固定，运行中修改设置只影响后续会话。
- 存储空间不足时停止采集并保留已有文件。
- 内核丢包、队列丢弃、截断和未归属分别统计；尚未取得内核统计时显示“未采样”。

工具没有固定的抓包时长上限，但持续时间受到存储、供电、系统后台策略及设备处理能力限制。零丢包计数只描述已观测的统计，不能单独证明网络端或采集过程绝对完整。

浏览列表每批加载 128 条，内存中最多保留 1536 条浏览记录；接近边缘自动换页并保留位置，稀疏匹配每批最多扫描 4096 条后让出执行。这是界面内存限制，**不会据此删除磁盘上的原始包**。分组最多汇总 2000 条连接，一次勾选最多 512 条；差异面板展示前 512 个变化位置并给出变化总数。

### 研究模式与自动报告

“设置 → 采集策略 → 独立保留未知归属包”默认关闭。开启后，只对应用关联模式生效，无法归属的包保存到会话的 `unattributed/`，可能含其他应用流量。

新连接的未知包先在 2 秒 / 8 MiB 有界暂存区内重试关联。超时、暂存满或停止时仍不明确的包，按开关保留或排除。每条已保存记录的 `attribution.jsonl` 包含 UID、精确/通配套接字匹配、决策时刻、等待时长、快照年龄、接口名称/索引与失败原因。依据是用户态 socket 快照，不能等同内核逐包 UID。

- “数据 → 更多 → 查看归属未知”进入独立数据目录，再点同一项返回主会话。
- 主会话导出的 PCAP 只含主会话包；未知视图可以单独导出其 PCAP。完整 ZIP 递归包含两者及证据。
- `network-events.jsonl` 记录系统可见的 Wi-Fi、移动网络、VPN、默认网络与接口变化；Android 16 使用公共热点/网络共享接口回调，旧系统或访问失败时写为 unavailable；具体系统行为仍待手机验证。
- 停止后自动生成 `integrity.txt` / `integrity.json`；手机可在抓包页或数据更多菜单打开。
- 报告区分文件记录边界/索引一致、已观察区间无缺口、可见缺口以及未覆盖/无法判断。经典 PCAP 没有结束标记，文件边界正常不等于所有流量已覆盖。
- TCP 区间检查可处理重传、乱序和常见 32 位回绕，但不替代流重组；连接复用/首尾未抓到会影响结论。
- KCP 只检查严格符合标准明文结构的候选数据，不识别加密/私有头/变体。IP 分片按标识分组，复用、重叠和长时间间隔从严标为无法判断。
- 每类最多 4096 组、全局最多 200000 个区间；超限写入资源限制计数，不能把未覆盖部分算作连续。
- Linux PACKET_STATISTICS 每次读取会重置内核计数；实现累加每次增量，并保存读取成功/失败次数。内核统计涵盖采集 socket 的链路流量，不能直接当作游戏端的丢包率。

测试流与验收步骤见 [WORKBENCH.md](WORKBENCH.md)。

## 当前限制

### 应用流量归属

底层使用 `AF_PACKET / SOCK_DGRAM` 采集原始 IP 包，该接口不直接提供可靠的逐包 PID。应用模式通过 `/proc/net/tcp`、`udp`、`tcp6`、`udp6` 的 UID、协议及通信地址进行关联。

短暂存在的连接、分片、共享 UID、隔离进程及 VPN 等情况可能无法准确关联。同一 UID 可能包含多个相关进程；不同 UID 的子进程不能因为父子关系就自动视为已覆盖。当前不能保证指定应用绝对不漏包或实现严格的进程隔离。

整机模式也受内核丢包、接口与观测位置影响。选择所有接口时，同一数据可能在回环、VPN 等多个接口被重复观察。

### 协议与恢复能力

当前未实现：

- 通用游戏协议自动解释、通用/完整 TCP 流重组或 KCP 重组；TLS页只实现有界的单连接连续前缀重组。
- TLS 解密或 AI 分析。
- PCAPNG 导入。
- 完整的断电恢复与损坏索引自动重建。

单条记录上限为 **256 KiB**，与采集 snaplen 一致。程序被系统回收、异常断电或发生写盘故障时，可能留下部分文件，需要检查会话状态和原始文件，不能将其视作已完整保存的会话。

## 从源码构建

当前提供 **Windows PowerShell 构建脚本**，直接调用 Android SDK / NDK 工具，没有 Gradle Wrapper，也没有第三方 Java UI 依赖。

所需环境：

| 工具 | 版本 |
| --- | --- |
| JDK | 17 或更高版本 |
| Android SDK Platform | 36 |
| Android SDK Build Tools | 36.0.0 |
| Android NDK | 29.0.14206865 |

在项目根目录执行，按本机安装位置修改路径：

```powershell
.\build.ps1 -SdkPath 'D:\Android\SDK' -JdkPath 'D:\Android\Android studio\jbr'
```

只构建 arm64 手机核心：

```powershell
.\build.ps1 -SdkPath 'D:\Android\SDK' -JdkPath 'D:\Android\Android studio\jbr' -SkipX86
```

输出文件：

```text
build/outputs/NetCap-0.5.0-mcp-test.apk
```

原生核心以 `libnetcap_core.so` 文件名打包，其实际格式是可执行 ELF，由 APK 解包后通过 `su` 启动；最终用户不需要手动复制或执行它。

构建会在 `build/signing/` 生成本地开发密钥。当前安装包是可调试的开发测试构建，保留显式调用的自检入口。正式发行仍需设备验收、独立正式签名、关闭调试与测试入口，并明确版本升级策略。尚未提供经过验证的手机本地编译流程。
